The problem

During a migration, an incident-response agent learns that a critical pipeline belongs to an engineer who has left, and routes alerts to nobody for three weeks. Operators cannot say when it learned this, from what source, what it believed before, or how to restore the correct state with proof.

Common memory services keep facts in vendor schemas, keep no content-hash link to the source, and accept agent writes without review. contextctl targets four properties together:

  1. Custodyof the source bytes behind each belief, by SHA-256.
  2. Authorizationan explicit review step before machine-written knowledge becomes trusted.
  3. Reconstructionof what was believed, and when, on two time axes.
  4. Minimal contextserving only what a task needs, by progressive disclosure.

No single mechanism is new; the combination is the point.

Four layers, one job each

Generation is untrusted. Curation is the only path into trusted state. The sidecar is a cache you can delete and rebuild. Serving may only propose writes, which re-enter staging.

Evidence object
Connectors store the raw bytes at evidence/<h>, where h is the SHA-256 of those bytes only. A retried fetch is idempotent; an edited source becomes a new object and the old one is kept.
OKF-MEM header
Concepts are markdown files in the Open Knowledge Format with memory fields: actor, evidence, sources, confidence, supersedes, and validity dates.
Write gate
Admission is a git merge --no-ff into main. Every merge is a snapshot: the transaction-time record.

Reconciliation: dedupe before a human sees it

Each draft is compared with the top-10 full-text matches and the same-path concept, using TF-IDF cosine similarity and the fact fields both assert with different values. Provenance fields never raise a conflict. The first matching rule applies.

1 · Conflict

a fact field differs from the same-path concept

Show both values; a human resolves; supersedes is recorded.

2 · Duplicate

max sim ≥ 0.9 and no new facts

Drop the draft and log the match.

3 · Revision

0.5 ≤ max sim < 0.9

Rewrite as an edit of the best match.

4 · New

max sim < 0.5

Add as a new concept.

A Duplicate or Revision whose best match is a different concept (a rename or a sibling) is held for review rather than applied.

As-of reads on two time axes

A post-merge hook maintains one SQLite file: an SCD Type 2 belief_history table over header fields and a body digest, an FTS5 index and a link table. Valid time comes from headers; transaction time comes from Git.

“What was the expression on t?” is one range query:

SELECT new_value FROM belief_history
 WHERE concept = :c AND field = 'expr'
   AND valid_from <= :t
   AND (valid_to IS NULL OR valid_to > :t);

“What did the bundle say then?” is an as-of read at that snapshot: contextctl read PATH --as-of 2024-08-01. With a retroactive valid_from, the two answers differ exactly over the period in which the agent was wrong.

Results

Measured in the paper on the built core with no language model: storage, versioning, indexing and the gate. They show the substrate works; they are not evidence for accuracy, token savings or the proposed integrity properties.

373drafts replayed from the public dbt Jaffle Shop history
322classified Duplicate (16 New, 24 Revision, 11 Conflict)
665/665as-of reads matched git show
155 mssnapshot commit at 104 concepts (634 ms at 105)
< 1 sfull sidecar rebuild; sub-ms point-in-time queries
9/9no-model lifecycle checks passed; rebuild matched row for row

What the replay taught us

  • (a) Checking Conflict against every candidate flagged 359 of 373 drafts, so Conflict is scoped to the same path.
  • (b) A coordinated header-and-blob rewrite passed the digest check and showed only as an uncommitted Git change.
  • (c) The full governed bundle cost about 4.6× the tokens of the raw sources: digests and URIs tokenize poorly.
  • (d) Reverting one merge conflicted with a later merge of the same files.

Reproduced with this repository

Reproduced (this implementation) A clean re-implementation from the paper's text, re-run on a fully synthetic project and on the same public dbt history. With --profile paper (one concept per metric, the pinned commit replayed, held renames approved, body-only similarity, plus the MetricFlow values for the final step) the public replay reproduces the paper's counts exactly: 373 drafts (16 / 322 / 24 / 11) and 665/665 as-of reads. The default configuration harvests every semantic model, measure and metric, so its counts are larger; examples/results/RESULTS.md attributes each difference to one setting.

Quickstart

Python 3.10+, Git and SQLite (with FTS5, standard in CPython). No services and nothing paid.

git clone {{REPO_URL}}.git
cd contextctl
python -m venv .venv && . .venv/bin/activate
pip install -e '.[tokens]'

contextctl selfcheck          # nine-check lifecycle
bash examples/quickstart.sh   # four layers on synthetic notes
contextctl replay --repeats 3 # replay harness, deterministic

Paper

contextctl: Auditable, Open-Format Context Infrastructure for AI Agents

Demo paper, AAI-BD workshop at the 2026 IEEE International Conference on Big Data (BigData 2026).

AI agents act on remembered facts, yet common memory services keep those facts in vendor schemas, keep no content-hash link to the source, and accept agent writes without review. We demonstrate contextctl, which manages agent context as governed data: markdown concept files in the Open Knowledge Format (OKF), Git as write gate and transaction-time record, a content-addressed evidence folder, and a rebuildable SQLite sidecar holding SCD Type 2 history. The demo runs the storage, versioning, indexing, and a minimal review gate with no language model, including a replay of a public dbt project's history.
